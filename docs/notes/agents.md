# Connecting agents with a click

Settings › Agents › Connect an agent, and the sidebar's card while no agent can reach Pinky (2026-11-08, branch `claude/agent-one-click-48058d`). What people get is in [docs/mcp.md](../mcp.md#connecting-an-agent); this note is how it is built and what was tried.

## Code

- `internal/agents`: the agents Pinky knows (`catalog.go`), finding them and their state (`Setup.Find`), Connect and Remove (`setup.go`, `agent.go`), the settings files (`store.go`), and the MCP bundle for Claude Desktop (`bundle.go`).
  - `jsonc.go` changes one member of an object in a JSON file that may have comments and trailing commas, by its byte span, and leaves every other byte as it was; `toml.go` does the same for a table of Codex's `config.toml`, line by line. Both read the file before and after the change and refuse it unless everything but Pinky's entry reads the same, and both refuse a file they cannot read. `files.go` writes through a temporary file and a rename, keeps the file's mode, follows a symbolic link (dotfiles kept in a repository stay links), keeps the copies (`<data>/agents/backups/<agent>/`, ten each) and installs or removes the skill, never one whose front matter names another skill.
  - `env.go` is the computer as `Setup` sees it, so that tests run on a home folder of their own. An app opened from the Dock has only the system's `PATH`: `searchPath` asks the person's login shell for its `PATH` once (`$SHELL -l -i -c`, 5 s at most, stdin closed), then adds this process's and the folders installers use (`~/.local/bin`, Homebrew, npm, bun, Volta, pnpm, nvm, WinGet's links). On Windows it skips `WindowsApps`, where `claude.exe` may be Claude Desktop's app alias. `PINKY_AGENTS_PATH` is the whole search path for tests, and nothing outside it runs then.
  - An agent's state comes from reading its settings (cached by content: `~/.claude.json` can be megabytes), never from `claude mcp list` or `get`, which start every server to check it.
- `ui/connect.go`: the part of Settings › Agents, the sidebar's card (`agentCard`, above the update cards) and the line under Tasks (`ui/rightpanel.go`). Until an agent has connected, Settings › Agents puts Connect an agent right under the empty list, which says to connect one below, and Ask Pinky after it, since Ask Pinky fills the window and left Connect an agent out of sight (until 2026-11-12); once one has connected, Ask Pinky comes first again (`settingsAgents`; both parts are keyed, so they keep their state as they change places). `ui.Options.AgentSetup` is nil in tests and the demo, which then show only the commands to add an agent by hand; `cmd/pinky/agents.go` makes the real one.
- `internal/mcp/list.go`: `mcp.Tools`, the tools as agents see them without a gateway, for the bundle's manifest. `scripts/release mcpb` writes the release's bundle; the release workflow's publish job and `scripts/release.sh build` run it.
- The skill is `docs/SKILL.md`, embedded as `pinky.Skill` (`skill.go` at the root). `Setup.RefreshSkills` rewrites every old copy of Pinky's (front matter `name: pinky`, other text) in the agents' skills folders, each folder once, and never makes one or touches someone else's; `cmd/pinky` `refreshSkills` runs it in the background when the app or the daemon starts, except in `…-dev` builds and under `PINKY_HOME`, so branches and tests never rewrite the person's copies. The Claude Desktop bundle carries no skill (the MCP server's instructions come from the running Pinky), so nothing there goes stale.

## Decisions

- **Each agent's own command first** (`claude mcp add --scope user`, `codex mcp add`, `copilot mcp add`, `gemini mcp add --scope user`): Claude Code locks `~/.claude.json` while it writes it (2.1.318), and other sessions of it write the file all the time. Pinky backs the file up before the command runs too. `codex mcp add` drops the comments of other `[mcp_servers.*]` tables (tried with codex-cli 0.167.0); the copy keeps them. Pinky removes a wrong entry before adding, as `claude mcp add` refuses a name it has.
- **`--scope user`** everywhere: Claude Code's default scope is the folder it runs in, which an app runs in `/`, and Gemini CLI's is the project.
- **Claude Desktop gets an extension, not a settings change.** It reads `claude_desktop_config.json` once and writes all of it back from memory whenever it saves a preference, so an entry written while it runs is lost (read from Claude Desktop 4.23118.0's code by the research for this). Connect writes a bundle made for this Pinky and opens it in Claude Desktop, which asks the person to install it; Pinky finds it in `Claude Extensions/*/manifest.json` (name `pinky`) and whether it is on in `Claude Extensions Settings/<id>.json`. A `pinky` entry in the settings file comes first in Claude Desktop, so Pinky sets that one right where it is. On Windows the data folder depends on the installer (`%APPDATA%\Claude`, MSIX's `%LOCALAPPDATA%\Claude-Data\<package>`, the Store's `Packages\…\LocalCache\Roaming\Claude`): Pinky takes the one whose settings changed last.
- **Skills:** `~/.claude/skills` for Claude Code, which reads only that; `~/.agents/skills` for Codex, Cursor, VS Code, Copilot CLI, Gemini CLI and Devin, which all read it. Cursor and VS Code also read `~/.claude/skills`, so with Claude Code connected they see the same skill twice.
- **VS Code** writes Copilot's global `~/.copilot/mcp-config.json`, which VS Code (`chat.mcp.discovery`, 1.145) and Copilot CLI both read, unless VS Code's own `User/mcp.json` has a `pinky` entry: two would collide (`chat.mcp.collisionBehavior` turns one off).
- **Windsurf** became Devin Desktop in June 2026: Pinky writes `~/.config/devin/mcp_config.json` when Devin is here, else Windsurf's `~/.codeium/windsurf/mcp_config.json`, which Devin also reads.
- **Gemini CLI** is found by its command only: `~/.gemini` is Antigravity's too.
- Nothing changes without a click: the card, Settings and the line under Tasks only read.

## Checked

- `go test ./internal/agents`: the editors (comments, trailing commas, CRLF, a byte order mark, tabs, one-line files, an empty file, a file of comments only, refusals of broken files, of duplicate names, of inline TOML tables), backups, symbolic links, the skill of someone else, the shared skill, every agent's paths on each system (fake environments), Claude Code through a fake command, Codex without one, Claude Desktop's bundle, extension and Windows folder, VS Code's two files, Windows' app aliases, the bundle and its launcher (in a folder of the test's own, never the Pinky in Applications).
- `go test ./ui -run 'TestConnect|TestAgentCard|TestTasksSay'`: the rows and their buttons, Connect, Update, Remove, a failure, the copy, Claude Desktop's extension, the card for one agent, several, none and one whose entry is broken, Not now, the line under Tasks. `TestConnectAgentsInView`: with no agent connected, Connect an agent's words and its first Connect (or Get) show whole without scrolling at 1280×820 and 960×620 in each language, before Ask Pinky. `PINKY_SCREENSHOTS=<dir> go test ./ui -run TestAgentSetupScreenshots` draws them in English and Chinese.
- `go test -tags e2e -run TestAgentSetupInTheApp ./cmd/pinky`: the e2e build of the app with a home folder of its own holding a fake `claude`, Codex's `config.toml` and Cursor's `mcp.json`: the card, Choose…, Connect for each (by the app's path, the rest of each file as it was, the copy, the skills), Remove, and the next start.
- Not tried on this Mac's real agents, by design: the tests never read or change the person's settings. Not tried on Windows or Linux beyond the path tests. Not tried: opening the bundle in a real Claude Desktop (MCPB's specification and Claude Desktop's code say a bundle may start a program outside it, and `${HOME}` works there although `mcpb validate` refuses it), `copilot mcp add` (its behaviour with a name it has is not documented), Devin's CLI (not used: its `remove` is not documented).

## Follow-ups

- Antigravity (`~/.gemini/config/mcp_config.json`, skills in `~/.gemini/config/skills`), opencode (two formats of `mcp`), Zed (`context_servers` in a large shared settings file), Kiro, Cline, Factory Droid, Qwen Code.
- Claude Code entries of the folder scope (`projects[…].mcpServers` in `~/.claude.json`), which the old instructions made (`claude mcp add` without `--scope`): Pinky does not list or fix them, and one in a folder wins over the user scope's there.
- Install links where an agent has one (Cursor's `cursor://anysphere.cursor-deeplink/mcp/install`, VS Code's `vscode:mcp/install`), which ask the person in the agent instead of a file change.
